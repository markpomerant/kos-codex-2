# Service Caching

Every lifecycle request's response is retained by the framework for the model.
`cache` decides how long it stays: `retention` names the policy, `ttl` the
lifetime for `TTL` retention, `extendOnRefresh` whether a repeat request keeps
the existing data and only extends its lifetime, and `maxSize` is reserved.

Caching belongs to lifecycle-driven requests. The method-driven form performs
the call and hands back the result; nothing is retained.

## The retention policies

Every lifecycle response is retained under its method and path, with the time
the request was sent and the time the response arrived. The policy decides
when that entry is removed.

### IMMEDIATE

The entry is removed as soon as the handler has returned. It exists while the
handler runs, including an async handler, and no longer. Use it for a
one-time operation whose response has no later reader.

### SINGLE (the default)

The entry stays until the next response for the same path replaces it. This
is what a request gets with no `cache` option.

### TTL

The entry stays for `ttl` milliseconds and is then removed by a timer; a read
after the deadline also removes it. Each new response replaces the entry and
restarts the clock.

With `extendOnRefresh: true`, a new response that arrives while the entry is
still valid does not replace it: the existing entry is kept and its deadline
moves out by another `ttl`. The handler still receives the new response; only
the retained copy is the earlier one. Use it when the retained value is the
expensive one and a refresh is only a heartbeat.

### PERMANENT

The entry stays until the model is destroyed. Use it for data the model needs
for its whole lifetime.

### MANUAL

The entry stays until the model clears it with `clearServiceResponse`. Use it
when the model decides when a response is stale.

## Who reads a retained response

The framework does. `requiresBaseline` on a topic handler reads the retained
response's request and receipt times to decide which queued events to replay
(the Lifecycle Race Conditions page). A model that needs a retained response
reads it through the SDK's `getServiceResponse` and `hasCachedResponse`
helpers and clears one with `clearServiceResponse`; it does not reach into the
store itself. `maxSize` is declared for a future per-path bound and is not read
by the SDK yet.

The SDK does not log a retained or extended response, so there is no console
line to look for on this page.
