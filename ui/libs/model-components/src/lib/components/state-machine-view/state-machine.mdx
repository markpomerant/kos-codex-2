# State Machine

A model whose lifecycle has named phases declares them as a machine.
`@kosStateMachine` takes the `initial` state, a `states` map of the events
each state accepts and where they lead, and `initializeAt`, the model
lifecycle phase at which the machine starts. Until then `currentState` is
undefined and `isFsmInitialized` is false.

`transition(event)` moves the machine; an event the current state does not
list is invalid. `throwOnInvalid` belongs to the machine's options, the
second decorator argument, and a guard can override it per method.

## How it was built

**Scaffold.**

```bash
kosui model --name session --project core-concept-models
```

**The machine, guards and handlers.** Written on the model by hand.

**Register, hook, component.** Register `session` in the app's registration chain.

```bash
kosui model:hook --modelName session --project model-components
kosui component --name state-machine-view --project model-components
```

## The machine

`@kosStateMachine<SessionState, SessionEvent>` sits under `@kosModel`. Its
first argument is the configuration: `initial` names the starting state,
`initializeAt` the lifecycle phase at which the machine starts, and `states`
maps each state to the events it accepts and where each leads. `closed` lists
nothing, so it is terminal. The second argument is the machine's options;
`throwOnInvalid: false` makes a rejected event a logged no-op rather than an
exception.

## Entry and exit

`@kosStateEntry(state)` and `@kosStateExit(state)` run on the way in and out.
An async entry handler can drive the next transition through the state's
`onDone` and `onError` events.
